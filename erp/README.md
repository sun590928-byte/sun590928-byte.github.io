# 午月營運帳務系統（ERP）

咖啡廳專用的「營運分析＋會計帳務」網頁系統。POS 銷售明細、綠界／LINE Pay 撥款、銀行存摺、電子發票、實體發票照片都匯進同一套資料，自動產生傳票與報表。

- 網址（GitHub Pages 合併到 main 後）：`https://sun590928-byte.github.io/erp/`
- 不需安裝、不需建置，瀏覽器打開即可用；手機也可以看。
- **預設資料只存在你這台電腦的瀏覽器**，不會上傳。之後可連線你自己的 Supabase 雲端資料庫，多台裝置共用，也能用 AI 辨識發票照片。

> 本系統的會計項目、稅務期限與分錄方式為**建議版本**，申報前請與記帳士確認。

## 二、第一次使用（約 20 分鐘）

1. 打開網址 → 左側 **設定與備份**：
   - 確認 **營業稅類型**：開立統一發票選「一般稅額（5% 內含）」；國稅局查定課徵選「小規模營業人」。這會影響營收入帳方式，**請先確認**。
   - 填入 **統一編號**（電子發票判斷可扣抵進項稅額用）、組織型態、是否有員工。
   - 營收起算日已預設 `2026-08-21`。
2. **匯入中心**：把下列檔案拖進去（可一次多個，同格式檔案之後會自動套用欄位對應）：

   | 你的檔案 | 系統判斷為 |
   |---|---|
   | `.csv之銷售明細` 資料夾內的 CSV（可按「選擇整個資料夾」） | POS 銷售明細 |
   | `綠界刷卡明細-20260801-20260922.csv` | 綠界刷卡明細 |
   | `綠界刷卡撥款明細-20260801-20260922.csv` | 撥款明細 |
   | `午月會計系統AI版 _更新日1150922.xlsx` | 選擇工作表後，類型選「會計分錄（舊帳匯入）」、「固定資產清單」等 |
   | 網銀下載的存摺明細 | 銀行存摺明細 |
   | 財政部電子發票平台下載的發票明細 | 電子發票（自動辨識 M｜D 格式） |
   | 照片、PDF | 自動轉到「憑證歸檔」 |

   每次匯入前會先預覽：可匯入幾筆、重複略過幾筆、作廢（老闆測試／招待／報廢）幾筆。重複匯入同一期間不會重複計算。
3. **品項整併**：逐組確認疑似同品項 → 按「合併選取」。分數較低的品名預設不勾，請自己判斷。「匯出疑似清單」可下載 CSV 在 Excel 裡看。
4. **日記簿 → 期初開帳**：輸入 8/20（起算日前一天）的現金、銀行、在途刷卡款、存貨、設備、押金等餘額。
5. **固定資產與折舊**：登錄咖啡機、磨豆機、製冰機、裝潢等，系統每月自動提列折舊。
6. `行動支付撥款明細-20260801-20260917.jpg`：連雲端後在「憑證歸檔」用 AI 讀出撥款；或在「金流對帳 → 登錄撥款」手動輸入。

## 三、例行作業

**每天／每週**
- 匯入 POS 銷售明細 → 營收分錄自動產生（每營業日一張轉帳傳票）。
- 發票、收據拍照丟進「憑證歸檔」 → 覆核 → 「入帳並歸檔」（自動命名 `YYYYMMDD_廠商_摘要_發票號_金額元`，歸入「民國年/月」資料夾）。

**每月 5 日前（上月結帳）**
1. 匯入綠界刷卡明細、撥款明細、網銀存摺明細、電子發票。
2. 金流對帳：POS 刷卡 vs 綠界逐日差異、撥款 vs 存摺入帳。
3. 銀行存摺對帳：確認調節表差異為 0，未入帳項目「補登分錄」。
4. 月底盤點 → 「存貨與成本」輸入期末金額 → 產生成本分錄（老闆招待／測試／報廢的原料成本自動轉到交際費／研究發展費／報廢損失）。
5. 「每月結帳檢查」全部通過 → 「結帳並鎖定」。
6. 列印當月傳票、試算表、損益表、資產負債表。

**申報**：看「申報行事曆」（營業稅雙月 15 日、扣繳、勞健保、5 月所得稅……），可匯出 `.ics` 放進手機行事曆。

## 四、帳務規則摘要

- **作廢**：品名、選項、備註、付款方式、分類欄中含「老闆測試」「老闆招待」「報廢」→ 金額計 0、不入營收；數量仍計入原物料耗用。POS 狀態為作廢／取消／退款者同樣排除。
- **營收分錄**（一般稅額）：借 現金／在途款項（綠界、LINE Pay…），貸 各品類銷貨收入（含稅 ÷ 1.05）、銷項稅額；折扣列「銷貨折扣」。
- **撥款**：借 銀行存款、手續費，貸 在途款項。
- **折舊**：平均法，殘值預設「成本 ÷（耐用年數＋1）」。
- **成本**：定期盤存制，本月耗用＝期初＋進貨－期末盤點。
- 已鎖定月份的分錄不可修改，自動分錄也不再更新。

## 五、雲端與 AI（選用，建議）

需要：Supabase 帳號（免費方案即可）、Anthropic API 金鑰（AI 辨識發票用）。

1. 在 [supabase.com](https://supabase.com) 建立專案（Region 選 Tokyo 或 Singapore）。
2. 左側 **SQL Editor** → 貼上 `supabase/migrations/20260923000000_wuyue_erp_init.sql` 全部內容 → Run。
3. 同一個 SQL Editor 執行（換成你的 Email）：
   ```sql
   insert into public.app_users (email, role) values ('你的Email', 'owner');
   ```
   只有這張白名單上的 Email 能讀寫資料（資料列級權限 RLS 已設定好，也已實測陌生帳號讀不到任何資料）。
4. **Authentication → Users → Add user**：用同一個 Email 建立帳號並設定密碼。建議在 **Authentication → Sign In / Providers** 關閉「Allow new users to sign up」。
5. 部署 AI 辨識函式（需安裝 [Supabase CLI](https://supabase.com/docs/guides/cli)）：
   ```bash
   supabase login
   supabase link --project-ref 你的專案代號
   supabase secrets set ANTHROPIC_API_KEY=sk-ant-你的金鑰
   supabase functions deploy extract-document
   ```
   金鑰只存在 Supabase 伺服器端，網頁與 GitHub 上都不會出現。預設模型 `claude-opus-5`，可用 `supabase secrets set CLAUDE_MODEL=...` 更換。
6. 打開 ERP → **設定與備份 → 雲端資料庫**：填入 Project URL 與 anon public key（Settings → API）→ 啟用 → 登入。
7. 若之前已在本機匯入資料，按「把本機資料上傳到雲端」。

## 六、部署

- **GitHub Pages**（目前）：此 repo 已開啟 Pages，合併到 `main` 後即可在 `/erp/` 使用。

## 七、資料與隱私

- 這個 GitHub repo 是**公開**的，只放程式碼，**不要把銷售明細、發票、存摺等資料檔 commit 進來**（`.gitignore` 已擋下常見資料檔）。
- 本機模式資料存在瀏覽器（IndexedDB），清除瀏覽器資料會一併刪除，請定期在「設定與備份」下載備份 JSON。
- 雲端模式資料在你自己的 Supabase 專案，照片存在私有 Storage，須登入且在白名單才能讀取。

## 八、開發

```bash
node --test tests/*.test.mjs                               # 單元測試（帳務引擎、匯入、品項比對…）
NODE_PATH=$(npm root -g) node tests/e2e.mjs /tmp/shots/    # 以 Chromium 實際操作並截圖（需 playwright）
node tools/gen-schema.mjs                                  # 修改 erp/js/schema.js 後重新產生 SQL
```

架構：純 ES modules、無建置流程。`erp/js/lib/` 為可單獨測試的計算邏輯（CSV/Big5、xlsx 讀取、品項比對、複式簿記、折舊、存貨、對帳、稅務行事曆）；`erp/js/views/` 為各頁面；`erp/js/store.js` 同一套 API 支援本機 IndexedDB 與 Supabase。測試資料 `tests/fixtures/` 全為合成資料。
