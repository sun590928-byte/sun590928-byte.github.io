# 午月營運帳務系統（ERP）

咖啡廳專用的「營運分析＋會計帳務」網頁系統。POS 銷售明細、綠界／LINE Pay 撥款、銀行存摺、電子發票、實體發票照片都匯進同一套資料，自動產生傳票與報表。

- 網址：`https://sun590928-byte.github.io/erp/`
- 不需安裝、不需建置，瀏覽器打開即可用；手機也可以看、可以直接拍發票上傳。
- **開啟需要密碼**：第一次使用先設定「開啟密碼」，資料用這組密碼加密後才存進裝置；閒置會自動上鎖。
- 店家設定：**商號（獨資）、開立統一發票、營業稅 5%、自行申報**，每期目標 **10 日開始準備、12 日前完成**。

## 二、第一次使用（約 20 分鐘）

1. 打開網址 → **設定開啟密碼**（至少 8 個字，可用中文）→ 系統顯示 **25 碼復原碼**，請下載或抄下，放在安全的地方。忘記開啟密碼時只能用復原碼重設。
   - 資料存放位置選「這台裝置」：加密存在瀏覽器，不上傳任何地方。
   - 選「雲端同步」：需要先建立自己的 Supabase（見第六節），店裡電腦、手機可共用同一份帳。
2. **設定與備份**：填入**統一編號**（判斷進項發票可否扣抵）；營業稅類型已設為「一般稅額（5%）」、組織型態「商號」、自行申報、目標日 10／12 日，需要時可改。
3. **匯入中心**：把下列檔案拖進去（可一次多個，同格式檔案之後會自動套用欄位對應）：

   | 你的檔案 | 系統判斷為 |
   |---|---|
   | `.csv之銷售明細` 資料夾內的 CSV（可按「選擇整個資料夾」） | POS 銷售明細 |
   | `綠界刷卡明細-20260801-20260922.csv` | 綠界刷卡明細 |
   | `綠界刷卡撥款明細-20260801-20260922.csv` | 撥款明細 |
   | `午月會計系統AI版 _更新日1150922.xlsx` | 選擇工作表後，類型選「會計分錄（舊帳匯入）」、「固定資產清單」等 |
   | 網銀下載的存摺明細 | 銀行存摺明細 |
   | 財政部電子發票平台下載的發票明細 | 電子發票（自動辨識 M｜D 格式） |
   | 照片、PDF | 自動轉到「憑證歸檔」 |

   每次匯入前會先預覽：可匯入幾筆、重複略過幾筆、作廢（老闆測試／招待／報廢）幾筆。重複匯入同一期間不會重複計算。
4. **品項整併**：逐組確認疑似同品項 → 按「合併選取」。分數較低的品名預設不勾，請自己判斷。
5. **日記簿 → 期初開帳**：輸入 8/20（起算日前一天）的現金、銀行、在途刷卡款、存貨、設備、押金等餘額；7–8 月這一期營業稅中，8/21 前的銷項稅額列 2131、可扣抵進項稅額列 1261。
6. **固定資產與折舊**：登錄咖啡機、磨豆機、製冰機、裝潢等，系統每月自動提列折舊（見第四節）。
7. `行動支付撥款明細-20260801-20260917.jpg`：連雲端後在「憑證歸檔」用 AI 讀出撥款；或在「金流對帳 → 登錄撥款」手動輸入。

## 三、例行作業

**每天／每週**
- 匯入 POS 銷售明細 → 營收分錄自動產生（每營業日一張轉帳傳票）。
- 發票、收據用手機「拍照上傳」或拖進「憑證歸檔」 → 覆核 → 「入帳並歸檔」（自動命名 `YYYYMMDD_廠商_摘要_發票號_金額元`，歸入「民國年/月」資料夾）。
- 手動記帳（日記簿「新增分錄」）時，直接在分錄視窗附上發票或收據；日記簿「來源」選「⚠ 缺原始憑證」可找出還沒附憑證的分錄。

**每月 5 日前（上月結帳）**
1. 匯入綠界刷卡明細、撥款明細、網銀存摺明細、電子發票。
2. 金流對帳：POS 刷卡 vs 綠界逐日差異、撥款 vs 存摺入帳。
3. 銀行存摺對帳：確認調節表差異為 0，未入帳項目「補登分錄」。
4. 月底盤點 → 「存貨與成本」輸入期末金額 → 產生成本分錄（老闆招待／測試／報廢的原料成本自動轉到交際費／研究發展費／報廢損失）。
5. 「每月結帳檢查」全部通過 → 「下載本月帳冊（Excel）」→ 「結帳並鎖定」。

**營業稅（單月 10～12 日，自行申報）**
1. 1、3、5、7、9、11 月的 10 日開始準備：打開「營業稅申報（401）」，選上一期（例如 9–10 月）。
2. 登入財政部電子發票整合服務平台，核對本期銷項發票總額與進項發票，把平台的銷售額與銷項稅額填進「申報紀錄」。
3. 「申報前檢查」全部通過後，到財政部電子申報繳稅服務網申報 401，**目標 12 日前完成**（法定期限 15 日，遇假日順延）。
4. 回到工作表按「標記已申報」、「產生結轉分錄」；繳稅後「登錄繳稅」。溢付稅額中屬於固定資產者可申請退稅，其餘自動帶到下期留抵。
5. 其他申報（扣繳、勞健保、二代健保補充保費、5 月所得稅結算）看「申報行事曆」；首頁也會提醒即將到來的申報。有疑問可撥國稅局免付費電話 0800-000-321。

## 四、固定資產：附發票、手動建立購置分錄

1. 「固定資產與折舊」→「＋ 新增資產」→ 在視窗下方按「拍照」或「上傳檔案」附上購置發票（也可以從憑證匣選擇；已在憑證歸檔入帳的資產發票也能選）。檔名中的日期、廠商、發票號、金額會自動帶入。
2. 儲存後系統會問「要現在建立購置分錄嗎？」→ 分錄視窗已預填 **借 資產科目（未稅成本）、借 1261 進項稅額／貸 付款方式**，可以自行修改後再儲存。
3. 清單會顯示每項資產的「購置憑證」與「購置分錄」狀態；缺發票、缺分錄會在「每月結帳檢查」提醒。營收起算日前購置的資產列入「期初開帳」。
4. 所有上傳的發票、收據都會出現在「憑證歸檔」，入帳時自動命名歸檔，也會列在營業稅工作表的進項清單（固定資產進項稅額另外統計）。

## 五、帳務規則摘要

- **作廢**：品名、選項、備註、付款方式、分類欄中含「老闆測試」「老闆招待」「報廢」→ 金額計 0、不入營收；數量仍計入原物料耗用。POS 狀態為作廢／取消／退款者同樣排除。
- **營收分錄**（一般稅額）：借 現金／在途款項（綠界、LINE Pay…），貸 各品類銷貨收入（含稅 ÷ 1.05）、銷項稅額；折扣列「銷貨折扣」。
- **寄杯**：預設「收款時開立發票」（依法規），售出當天認列銷項稅額、預收款以未稅金額入帳；兌換時只把預收款轉為收入，不重複計稅。設定可改為「兌換時開立」。
- **進項稅額**：只有統一發票、載明本店統編、非交際應酬或職工福利用途者可扣抵（營業稅法第 19 條），其餘稅額併入成本。
- **撥款**：借 銀行存款、手續費，貸 在途款項。
- **折舊**：平均法，殘值預設「成本 ÷（耐用年數＋1）」。
- **成本**：定期盤存制，本月耗用＝期初＋進貨－期末盤點。
- 已鎖定月份的分錄不可修改，自動分錄也不再更新。

## 六、雲端與 AI（選用）

需要：Supabase 帳號（免費方案即可）、Anthropic API 金鑰（AI 辨識發票用）。

1. 在 [supabase.com](https://supabase.com) 建立專案（Region 選 Tokyo 或 Singapore）。
2. 左側 **SQL Editor** → 貼上 `supabase/migrations/20260923000000_wuyue_erp_init.sql` 全部內容 → Run。這份 SQL 可以重複執行：之後系統更新時再執行一次，就會補上新的資料表與欄位，既有資料不受影響。
3. 同一個 SQL Editor 執行（換成你的 Email）：
   ```sql
   insert into public.app_users (email, role) values ('你的Email', 'owner');
   ```
   只有這張白名單上的 Email 能讀寫資料（資料列級權限 RLS 已設定好，也已實測陌生帳號、未登入者都讀不到任何資料）。
4. **Authentication → Users → Add user**：用同一個 Email 建立帳號並設定密碼。到 **Authentication → Sign In / Providers** 關閉「Allow new users to sign up」（系統只接受 Email＋密碼登入，不開放自行註冊）。
5. 部署 AI 辨識函式：
   - 用 Supabase 後台：**Edge Functions → Deploy a new function → Via Editor**，名稱填 `extract-document`，貼上 `supabase/functions/extract-document/index.ts` 內容後部署；到 **Edge Functions → Secrets** 新增 `ANTHROPIC_API_KEY`。
   - 或用 [Supabase CLI](https://supabase.com/docs/guides/cli)：
     ```bash
     supabase login
     supabase link --project-ref 你的專案代號
     supabase secrets set ANTHROPIC_API_KEY=sk-ant-你的金鑰
     supabase secrets set ALLOWED_ORIGINS=https://sun590928-byte.github.io
     supabase functions deploy extract-document
     ```
   金鑰只存在 Supabase 伺服器端，網頁與 GitHub 上都不會出現。`ALLOWED_ORIGINS`（選用）限制只有你的網站能呼叫。預設模型 `claude-opus-5`，可用 `CLAUDE_MODEL` 更換。
6. 打開 ERP → **設定與備份 → 雲端資料庫**：填入 Project URL（`https://xxxx.supabase.co`）與 anon public key（Settings → API）→ 啟用 → 輸入開啟密碼 → 登入雲端帳號。之後這台裝置保持登入（加密保存），每次只要輸入開啟密碼。
7. 若之前已在本機匯入資料，按「把這台裝置的本機資料上傳到雲端」（照片一起上傳）。

## 七、資訊安全

| 保護對象 | 做法 |
|---|---|
| 開啟系統 | 需要**開啟密碼**；閒置（預設 30 分鐘，可調 5 分鐘～4 小時）自動上鎖；另開分頁時舊分頁自動上鎖。 |
| 這台裝置上的資料 | 帳務資料、憑證照片、雲端登入狀態一律以 **AES-256-GCM** 加密後才寫入瀏覽器；金鑰由開啟密碼經 PBKDF2（60 萬次）衍生，密碼本身不儲存。別人拿到電腦也讀不到內容。 |
| 忘記密碼 | 用 25 碼**復原碼**重設（重設後會換一組新的復原碼）；兩者都遺失時，只能清除這台裝置的資料、再從加密備份還原。 |
| 雲端資料 | 存在你自己的 Supabase；只有白名單帳號能讀寫（RLS），照片存私有空間，預覽連結 10 分鐘失效；不開放自行註冊。 |
| 備份檔 | 「下載加密備份」產生 `.wyb` 檔，以備份密碼加密（可含憑證照片），放 OneDrive 或隨身碟也安全。 |
| 網站本身 | 內容安全政策（CSP）只允許載入本站程式與 Supabase；禁止被其他網站嵌入；不被搜尋引擎收錄。 |

**關於公開的 GitHub repo**：repo 裡只有程式碼（就像 App 的安裝檔），**沒有任何營業資料、密碼或金鑰**（已掃描檢查過常見的金鑰格式）。GitHub 無法替 repo 設密碼；可以在 repo 的 **Settings → General → Danger Zone → Change visibility** 改成私有，但要注意：免費方案的私有 repo 無法使用 GitHub Pages（網站會下線，需 GitHub Pro 每月 US$4），而且即使改私有，網站網址仍是公開的。真正保護資料的是上表的開啟密碼、加密與雲端白名單。若想連網站入口都加一道門，可改用 Cloudflare Pages＋Cloudflare Access（免費，限定 Email 驗證後才能開網站）。

**請不要把銷售明細、發票、存摺等資料檔 commit 進 repo**（`.gitignore` 已擋下常見資料檔）。

## 十、開發

```bash
node --test tests/*.test.mjs                               # 單元測試（加密、營業稅、帳務引擎、匯入、品項比對…）
NODE_PATH=$(npm root -g) node tests/e2e.mjs /tmp/shots/    # 以 Chromium 實際操作並截圖（需 playwright）
node tools/gen-schema.mjs                                  # 修改 erp/js/schema.js 後重新產生 SQL
```

架構：純 ES modules、無建置流程。`erp/js/lib/` 為可單獨測試的計算邏輯（加密保管箱、CSV/Big5、xlsx 讀寫、品項比對、複式簿記、營業稅、折舊、存貨、對帳、稅務行事曆）；`erp/js/views/` 為各頁面；`erp/js/store.js` 同一套 API 支援加密的本機 IndexedDB 與 Supabase；`erp/js/gate.js` 為開啟密碼與登入畫面。測試資料 `tests/fixtures/` 全為合成資料。
