# 午月營運帳務系統（ERP）操作手冊

咖啡廳專用的「營運分析＋會計帳務」網頁系統。POS 銷售明細、綠界／LINE Pay 撥款、銀行存摺、電子發票、實體發票照片都匯進同一套資料，自動產生傳票與報表。

- 網址：`https://sun590928-byte.github.io/erp/`
- 不需安裝、不需建置，瀏覽器打開即可用；手機也可以看、可以直接拍發票上傳。
- **開啟需要密碼**：第一次使用先設定「開啟密碼」，資料用這組密碼加密後才存進裝置；閒置會自動上鎖。
- 店家設定：**商號（獨資）、開立統一發票、營業稅 5%、自行申報**，每期目標 **10 日開始準備、12 日前完成**。

這份手冊回答四件事：

1. 每個選單頁面做什麼（第一節）
2. 照什麼順序做（第二節）
3. 哪些按鈕會產生或修改傳票（第三節）
4. 做錯了怎麼更正（第四節）

第五節專門回答「在憑證歸檔入帳」和「在日記簿掛附件」有什麼不同、什麼時候用哪一個。第七節以後是第一次使用、帳務規則、雲端、資訊安全與開發說明。

---

## 〇、先記住七條規則

1. **一張發票或收據，只從一個地方入帳一次。** 有發票、收據的支出，一律在「憑證歸檔」入帳。
2. **日記簿「新增分錄」只做沒有發票收據的事**：薪資、勞健保、借還款、業主投入或提取、調整與更正分錄。
3. **自動產生的傳票不要手改**：POS 營收、撥款入帳、折舊、存貨成本、營業稅結轉。要改就改來源資料（銷售明細、撥款、資產、盤點），系統會自己重算。
4. **先資料、再對帳、最後結帳。** 每月先把 POS、撥款、存摺、發票都匯入並入帳，再做存貨、折舊、結帳檢查，最後鎖定。
5. **鎖定的月份不再動。** 發現錯誤，在還沒鎖定的月份（通常是本月）做更正分錄。**2026 年 6～10 月已鎖定，11 月起一律不解除。**
6. **已申報的營業稅期別，不改原始資料。** 要改，先向國稅局申請更正，再在本月做差額的更正分錄。
7. **刪除不會連動。** 在憑證歸檔刪照片，傳票不會跟著刪；在固定資產刪資產，購置傳票也不會跟著刪。要刪傳票，一律到日記簿。

## 一、每個選單頁面的用途

「不動傳票」表示這一頁的任何按鈕都不會產生或修改傳票。

### 總覽

- **營運儀表板**：每日營收、品類、付款方式、時段熱度、熱銷品、作廢統計、近期申報提醒、還沒設配方的品名。只看，不動傳票。

### 資料匯入

- **匯入中心**：把檔案拖進來。POS 銷售明細、綠界刷卡明細、撥款明細、存摺明細、電子發票、供應商、進貨單、舊帳、固定資產清單都在這裡匯入。匯入前先預覽：新增幾筆、重複略過幾筆、作廢幾筆。照片、PDF 會自動轉到「憑證歸檔」。下方「匯入紀錄」可以整批刪除匯錯的檔案。匯入 POS、撥款後，系統會自動重算 POS 營收與撥款傳票。
- **品項整併（選用）**：把同一商品的不同寫法（例如「美式」「美式咖啡」）合成一個品項，報表才不會分散。品項的品類決定營收科目，合併或改品類後會重算 POS 營收傳票。
- **憑證歸檔（AI）**：發票、收據照片與 PDF 的收件匣。上傳 → 本機辨識（QR 碼、文字）→ 覆核欄位 → 「入帳並歸檔」。分頁有待處理、已入帳、不入帳、全部、電子發票。**有發票收據的支出都從這裡入帳。**

### 營運分析

- **銷售明細與作廢**：查每一筆 POS 明細。老闆招待、老闆測試、報廢自動作廢（金額記 0，原料照算耗用）。可以「重新套用作廢規則」，也可以單筆「標記作廢」並寫原因。
- **金流對帳**：POS 刷卡金額和綠界逐日核對（可以用綠界撥款明細 CSV 的「交易日期」對日）、逐筆比對、撥款核對、撥款對存摺。LINE Pay 等沒有檔案的撥款，用「＋ 登錄撥款」手動輸入。
- **原物料進銷存**：庫存水位（期初＋進貨－耗用－報廢±盤點）、安全庫存預警、異動紀錄、盤點表列印與匯出、匯入盤點結果。表格比畫面寬時，「狀態」「修改」「＋異動」固定在表格右邊，表格上方也有一條橫向捲軸。不動傳票。
- **BOM 配方表**：每個 POS 品名用了哪些原料、各多少。POS 賣出份數 × 配方＝理論耗用。不動傳票。
- **供應商**：供應商基本資料與付款條件（匯款銀行、戶名、帳號）。不動傳票。
- **進貨紀錄**：登記或匯入進貨單，數量載入進銷存、追蹤單價。**只管數量與成本，不動傳票**；那張發票還是要在「憑證歸檔」入帳。
- **會員消費輪廓**：會員等級、累積消費、偏好、最後到店、行銷名單。
- **行銷活動成效**：活動期間、關鍵字、兌換率、帶動營收、ROI。
- **早午餐企劃、濾掛與禮盒企劃**：新品的試算、進度與測試紀錄。不動傳票。
- **營運損益**：用 POS 與成本估算的管理用損益（固定／變動成本、毛利、損益兩平）。這是經營判斷用的，和會計的「綜合損益表」不同。

### 會計帳務

- **會計項目**：科目表。新增、改名、停用、匯入匯出 CSV。有傳票用到的科目只能停用，不能刪。
- **日記簿**：全部傳票的清單。新增分錄、修改、刪除、列印單張、同步自動分錄、期初開帳、依日期重新編號、結帳並鎖定本月，12 月另有「產生年底結帳分錄」。「來源」可以篩選；選「⚠ 缺原始憑證」找出該附憑證卻沒附的傳票。
- **分類帳**：單一科目的明細與餘額。
- **試算表**：各科目借貸合計，確認借貸平衡。
- **資產負債表、綜合損益表**：正式報表，可匯出 Excel、列印。
- **傳票列印**：整月或單張傳票。每張傳票固定佔 A4 的一半，一頁上下各一張，中間印一條裁切虛線；分錄超過 12 行（半頁放不下）的傳票單獨印一整頁。
- **固定資產與折舊**：資產清單、每月折舊、購置發票與購置傳票的狀態。
- **存貨與成本**：月底輸入各存貨科目的期末盤點金額（或從進銷存帶入），產生當月「存貨成本」傳票。
- **銀行存摺對帳**：匯入網銀明細或存摺照片，自動勾稽帳上的分錄；帳上沒有的「補登分錄」；列印調節表。月底餘額取當天最後一列的結存。
- **每月結帳檢查**：二十多個檢查項目（能自動判斷的自動打勾，其他手動勾）、下載本月帳冊 Excel、結帳並鎖定、解除鎖定。
- **營業稅申報（401）**：銷項、進項清單、留抵、應納稅額、申報前檢查、產生申報媒體檔、匯入已申報媒體檔、國稅局進項發票核對、標記已申報、產生結轉分錄、登錄繳稅。
- **申報行事曆**：營業稅、扣繳、勞健保、二代健保、所得稅的期限與準備日，可匯出到手機行事曆。

### 系統

- **設定與備份**：店家資料、統編、營收起算日、營業稅類型、作廢關鍵字、付款方式預設、本機辨識選項、雲端資料庫、Claude 連接器、加密備份與還原。改了營收起算日、營業稅類型、銀行科目等設定，系統會重算全部自動分錄（已鎖定月份不動）。

## 二、正確的操作順序

### 1. 每天（或每週一次）

1. 匯入中心匯入 POS 銷售明細。系統自動做好「POS 營收」傳票，每個營業日一張。
2. 儀表板或匯入後若提醒「有品名還沒設配方」，到 BOM 配方表補上。
3. 發票、收據拍照上傳到憑證歸檔。可以先放著，週末再一起覆核入帳。

### 2. POS 資料進來時

1. 匯入中心 → 拖入 POS 檔 → 看預覽（新增、重複略過、作廢各幾筆）→ 匯入。
2. 到「銷售明細與作廢」看作廢明細：老闆招待、老闆測試、報廢有沒有判斷對。
3. 事後才作廢的訂單，兩種做法擇一：
   - 重新匯入那天的 POS 檔：已經變成作廢的訂單會更新。
   - 在那一筆按「作廢」，或按上方「依單號標記作廢」輸入日期和單號（例如 0878、0879），選原因、寫備註。
4. 月份還沒鎖定：POS 營收傳票自動重算。月份已鎖定：只更新銷售明細，傳票不重算，差額在本月做更正分錄（第四節第 6 點）。
5. 有新品名：到 BOM 配方表設配方。想把不同寫法合在一起看報表，才去做品項整併。

### 3. 發票、收據進來時

這是最容易重複入帳或漏登的地方，請照順序做。

1. **上傳**：憑證歸檔 →「拍照上傳」「選擇照片／PDF」或「選擇資料夾」。用資料夾上傳時，子資料夾名稱就是付款方式：
   - `員工代墊支出` → 2134 其他應付款－員工代墊
   - `負責人代墊支出` → 2133 其他應付款－負責人代墊
   - `○○銀行` → 名稱含「○○」的銀行存款科目
   - 同名檔案再上傳不會重複，只更新付款方式；`存摺明細` 資料夾的照片會送到銀行存摺對帳。
2. **辨識**：上傳後自動做本機辨識（不用外部 AI，照片不離開這台電腦）。有疑點的卡片標「需確認」，並寫出原因（附錄 B）。
3. **覆核每一張卡片**：日期、廠商、統編、發票號碼、含稅金額、稅額、會計項目、付款方式、可否扣抵。
   - 一張照片有好幾張發票，或一筆錢分屬好幾個科目 → 按「拆分明細」，一行一張發票或一個科目。拆分（或合併）的明細，每一行可以有自己的日期。
   - 老闆說先不認列 → 按「暫緩」，「全部入帳」會略過。
   - 不需要入帳的（重複的照片、對帳單）→ 按「不入帳」。
4. **入帳**：單張按「入帳並歸檔」，或按「全部入帳」一次處理欄位齊全的。系統會：
   - 產生一張「憑證」傳票：借 會計項目（未稅）、借 1261 進項稅額（可扣抵才有），貸 付款方式。
   - 自動判斷可否扣抵，存下課稅別與扣抵代號（401 進項清單直接用）。
   - 依「日期_廠商_摘要_發票號_金額」命名歸檔。
   - 同一個發票號碼已由電子發票入帳時，只連結照片，不重複入帳。
   - 會計項目是 15xx 固定資產時，問你「連結現有資產」或「新增資產」；同一個發票號碼已經有資產時會提醒。新增的資產從取得當月起自動提列折舊。
   - 「全部入帳」會略過 15xx 固定資產的憑證，這些要逐張按「入帳並歸檔」選擇連結或新增。
5. **電子發票**：匯入中心匯入財政部平台下載的進項發票 → 憑證歸檔「電子發票」分頁選會計項目 →「入帳」。已經有照片入帳的同號碼發票只會連結，不會再入帳一次。
6. **進貨單**：進貨紀錄登記或匯入，原料數量才會進庫存。這一步不動傳票，**傳票還是靠第 4 步把發票入帳**。

### 4. 銀行存摺（每月至少一次）

1. 匯入中心匯入網銀下載的存摺明細，或在「銀行存摺對帳」按「匯入存摺照片」。照片辨識後用結存逐列核對，只匯入打勾的列。
2. 系統自動勾稽：存摺每一列去找帳上對應的分錄（撥款、現金存入、轉帳付款）。核對沒問題就按「確認 ○ 筆自動勾稽」。
3. 對錯了按「取消」，再按「手動對應」選正確的分錄。
4. 帳上沒有的項目（銀行手續費、利息、轉帳付的房租…）按「補登分錄」，很多筆用「批次補登」。
   - **這筆支出有發票或收據時，不要補登。** 先到憑證歸檔入帳（付款方式選該銀行），再回來「手動對應」。補登＋憑證入帳＝重複入帳。
5. 調節表差異要是 0。月底餘額取當天最後一列的結存。

### 5. 月底結帳（每月 5 日前結上個月）

依序做，前一步沒完成不要往下：

1. **資料到齊**：POS 匯入到月底最後一天；綠界刷卡與撥款明細、存摺、電子發票都匯入；憑證歸檔「待處理」清空（或已暫緩）。
2. **金流對帳**：POS 刷卡和綠界逐日差異為 0，撥款都對到存摺。
3. **銀行存摺對帳**：調節表差異為 0。
4. **存貨與成本**：月底盤點 → 原物料進銷存「匯入盤點結果」，或在「存貨與成本」輸入期末盤點金額（可先按「帶入進銷存庫存價值」再核對）→ 按「產生本月成本分錄」。
5. **折舊**：到「固定資產與折舊」確認本月折舊已提列（新增、修改資產時系統會自動重算）。本月新買的資產要有購置發票與購置傳票。
6. **其他手動分錄**：薪資、勞健保、勞退；應付或預付費用（房租、水電、記帳費）；寄杯預收款核對。
7. **每月結帳檢查**：逐項看；沒有自動打勾的，確認後手動勾。試算表要平衡，資產＝負債＋權益。按「下載本月帳冊（Excel）」備份。
8. **結帳並鎖定**。鎖定後這個月的傳票不能新增、修改、刪除，自動分錄也不再更新。
9. 真的要改已鎖定的月份：每月結帳檢查有「解除鎖定」。**6～10 月不要解除**，用第四節的更正分錄。

### 6. 雙月營業稅 401（1、3、5、7、9、11 月的 10～12 日）

1. 先做完上一期兩個月的月底結帳（至少做到上面第 7 步）。
2. 打開「營業稅申報（401）」，選上一期（例如 9–10 月）。
3. **國稅局進項核對**：在匯入中心匯入財政部平台下載的進項發票 → 回到營業稅頁看「國稅局有、ERP 沒入帳」與「金額不符」。漏的按「入帳」（或回憑證歸檔補入帳）；金額不符的回去改憑證。
4. **核對銷項**：把平台上的銷售額與銷項稅額填進申報紀錄，和 POS 算出來的數字比對。
5. **申報前檢查**：列出的問題會附發票號碼與傳票號碼，點連結直接去改（例如不能扣抵卻記了 1261）。全部通過再往下。
6. **產生申報媒體檔（TXT）**：含進項、銷項、空白發票，到財政部電子申報繳稅服務網上傳申報。三聯式收銀機發票（格式代號 22）的稅額以含稅金額 ÷ 1.05 推算。
7. **申報完成**：按「標記已申報」；或按「匯入已申報媒體檔（TXT）」，系統會標記已申報、記下 401 數字，並逐張核對申報清單和系統憑證。
8. **產生結轉分錄**：把本期 2131 銷項稅額、1261 進項稅額結轉到應付營業稅或留抵。延後扣抵的發票，它的 1261 會留到實際申報扣抵那一期結轉時才轉出。
9. **繳稅後**按「登錄繳稅」。
10. 目標 12 日前完成；法定期限 15 日，遇假日順延。其他申報（扣繳、勞健保、二代健保、5 月所得稅）看「申報行事曆」。

進項清單的代號：**課稅別** 1 應稅、2 零稅率、3 免稅；**扣抵代號** 1 可扣抵進貨及費用、2 可扣抵固定資產、3 不可扣抵進貨及費用、4 不可扣抵固定資產。需要時可以在憑證上手動指定。

## 三、哪些按鈕會產生或修改傳票

**傳票種類**由系統依分錄自動判斷：借方全是現金或銀行（1101、1102、1103、1105）→ 現金收入傳票；貸方全是現金或銀行 → 現金支出傳票；其他都是轉帳傳票。

**來源**是日記簿與傳票上的「來源」欄。來源是 POS 營收、撥款入帳、折舊、存貨成本、年底結帳、營業稅結轉的叫「自動分錄」：日記簿只能「檢視」，不能手改、不能刪。

| 頁面 | 按鈕 | 傳票來源 | 做什麼 | 已鎖定的月份 |

| 匯入中心 | 匯入（POS 銷售明細） | POS 營收 | 依銷售明細重算，每營業日一張 | 略過，不更新 |

## 四、做錯時怎麼更正

先看月份：

- **還沒鎖定**：改來源（憑證、銷售明細、資產、盤點），讓系統重算；手動傳票直接在日記簿改或刪。
- **已經鎖定**：不解除。到日記簿選本月 →「＋ 新增分錄」，日期用本月，摘要寫「更正 115 年 9 月傳票 11509-0012：原因」，把錯的科目沖回、記到對的科目，附上原始憑證或說明。
- **營業稅已申報**：先向國稅局更正（第 9 點）。

### 1. 同一張發票入帳兩次

常見原因：憑證歸檔入帳一次，日記簿又手打一次；或照片和電子發票各入帳一次。系統會擋一部分：同發票號碼已由電子發票入帳，照片只會連結；日記簿附上已入帳的憑證時會提醒「已由其他分錄入帳」。

- 未鎖定：日記簿搜尋發票號碼，找到多的那張 → 刪除。保留憑證歸檔產生的那張（它有扣抵判斷與 401 資料）。被刪傳票上的憑證會回到「待處理」；那是重複的照片，就按「不入帳」。
- 已鎖定：本月做一張借貸對調的更正分錄，把多的那張沖掉。多記的 1261 若已申報扣抵，再看第 9 點。

### 2. 會計項目或付款方式選錯

- 憑證入帳的傳票：日記簿 → 修改 → 在視窗裡改會計項目或付款方式 → 儲存並同步。憑證、傳票（號碼不變）、401 一起改。
- 手動、存摺補登的傳票：日記簿 → 修改 → 改科目 → 儲存。
- POS 營收：品類錯 → 品項整併改品類；付款方式錯 → 修正 POS 資料後重新匯入。傳票會自己重算。
- 已鎖定：本月更正分錄：借 正確科目，貸 錯的科目（付款方式錯就對調兩個付款科目）。

### 3. 可否扣抵、稅額、扣抵代號判斷錯

- 日記簿 → 修改（憑證傳票）→ 改課稅別、扣抵代號、稅額 → 儲存並同步。可扣抵：稅額記 1261；不可扣抵：稅額併入費用或成本。
- 該期已申報：系統只提醒，不會改申報紀錄。少扣的發票會順延到之後第一個還沒申報的期別扣抵；多扣的要向國稅局更正（第 9 點）。
- 已鎖定：本月更正分錄，例如不該扣抵卻扣了：借 原費用科目，貸 1261。

### 4. 憑證掛錯傳票

- 手動、補登的傳票：日記簿 → 修改掛錯的那張 → 附件區把憑證拿掉 → 儲存（憑證回到「待處理」）→ 修改正確的那張 → 從憑證匣選那張憑證 → 儲存。
- 自動分錄：按「檢視」→ 改附件 →「儲存附件」。
- 來源是「憑證」的傳票，是那張憑證自己產生的。整張入錯（例如入成別張發票的金額）→ 刪除這張傳票，憑證回到待處理，改好欄位再入帳一次。
- 已鎖定：附件改不了。金額沒錯，就在本月「每月結帳檢查」的備註記下正確對應（例：「115/9 傳票 11509-0012 的附件應為 11509-0013」）；金額也錯，照第 1、2 點在本月更正。

### 5. 固定資產重複

同一台設備在「固定資產與折舊」手動新增一次，憑證入帳時又自動建立一次，折舊就會算兩次。

- 預防：入帳 15xx 憑證時，系統會問「連結現有資產」或「新增資產」，同發票號碼已有資產也會提醒——已經登錄過的設備，選「連結現有資產」。
- 已經重複：固定資產與折舊 → 刪除多的那筆（保留有購置發票、購置傳票的那筆）→ 未鎖定月份的折舊自動重算。多的那筆若有自己的購置傳票，到日記簿刪掉。
- 已鎖定月份多提的折舊：本月更正分錄：借 累計折舊，貸 6124 折舊費用。

### 6. POS 訂單事後作廢

- 重新匯入那天的 POS 檔（已作廢的訂單會更新），或在「銷售明細與作廢」那一筆按「標記作廢」並寫原因。
- 月份未鎖定：POS 營收傳票自動重算，不用另外處理。
- 已鎖定：只更新銷售明細（報表與耗用數字會對），傳票不重算。在本月做更正分錄：借 銷貨收入（未稅）、借 2131 銷項稅額，貸 1105 現金或應收帳款（看當初怎麼收的錢）。
- 發票已經開立的，依規定作廢發票或開銷貨折讓單；該期營業稅已申報，再看第 9 點。

### 7. 盤點數字錯

- 未鎖定：重新匯入正確的盤點表（同一個盤點日會取代，不會重複），或在「存貨與成本」改期末盤點金額 → 按「更新本月成本分錄」（同一張傳票會更新）。
- 已鎖定：不用改舊月份。下個月盤點正確後，差額會自動進下個月的銷貨成本（定期盤存制）。金額大的，在下個月結帳檢查的備註寫明原因。

### 8. 已鎖定月份發現錯誤（2026 年 6～10 月）

- **不要解除鎖定。** 解除後自動分錄會依目前資料重算，已經交給會計師或已申報的數字會跟著變。
- 做法：日記簿選本月 →「＋ 新增分錄」→ 日期用本月 → 摘要寫「更正 115 年 ○ 月傳票 ○○○○○-○○○○：原因」→ 把錯的科目沖回、記到對的科目 → 附上原始憑證或說明 → 儲存。
- 只影響科目分類、不影響稅額的小錯誤，可以累積到月底一次更正。
- 11 月起，6～10 月一律不解除鎖定。11 月以後的月份真的要解除：到「每月結帳檢查」按「解除鎖定」，改完馬上重新鎖定。

### 9. 已申報的營業稅期別有錯

- **不要用「取消申報標記」來改數字。** 那只是系統裡的紀錄，國稅局的申報不會因此改變。
- 漏報進項（漏了發票）：照常入帳。系統會把它順延到之後第一個未申報期別扣抵（延後扣抵）。
- 多報進項、銷項報錯、發票號碼或代號打錯：向國稅局所在地分局申請更正申報，用正確的媒體檔重新上傳。國稅局接受後：
  1. 在本月做差額的更正分錄（2132 應付營業稅、1261 進項稅額、2131 銷項稅額，看錯在哪裡）。
  2. 用「匯入已申報媒體檔（TXT）」匯入更正後的媒體檔，讓系統的申報紀錄和國稅局一致。
- 有疑問打國稅局免付費電話 0800-000-321。

### 10. 匯入錯檔

- 同一份檔案重複匯入不會重複計算，預覽會顯示「重複略過」。
- 匯錯檔：匯入中心 → 匯入紀錄 → 那一批按「刪除」。POS、撥款的傳票會重算（已鎖定月份不動）。
- 那一批只要有任何一筆在已鎖定的月份，系統就不讓你刪，以免改到已結帳的帳。6～10 月的資料匯錯，用本月更正分錄處理。

### 11. 傳票號碼亂了

- 日記簿 → 選月份 →「依日期重新編號」。已列印的傳票號碼會變，要重印。已鎖定的月份不能重新編號。

## 五、「憑證歸檔入帳」和「日記簿掛附件」怎麼選

兩個地方都能讓一張發票「掛在傳票上」，但產生的傳票不一樣：

| | 憑證歸檔「入帳並歸檔」 | 日記簿「＋ 新增分錄」再掛附件 |
|---|---|---|
| 傳票內容 | 系統依憑證欄位產生：借 科目（未稅）＋ 1261（可扣抵才有），貸 付款方式 | 你打的每一行，系統不改 |
| 進項稅額 | 自動判斷可否扣抵（本店統編、三聯式、交際費、伙食費、水電沒有本店統編…），存下課稅別、扣抵代號 | 不判斷。打了 1261 就記 1261，打錯也照記 |
| 401 進項清單 | 依憑證欄位列入，和傳票一致 | 依憑證卡片上的欄位列入（常常沒覆核、稅額空白），可能和傳票的 1261 對不上，申報前檢查會報錯 |
| 固定資產（15xx） | 連結或新增資產，自動提列折舊 | 不建立資產 |
| 歸檔命名 | 有 | 有 |
| 傳票來源 | 憑證 | 手動 |
| 之後修改 | 日記簿「修改」→ 儲存並同步：憑證、傳票、401 一起改 | 日記簿「修改」：只改傳票 |
| 重複保護 | 同發票號碼已入帳時只連結，不再入帳 | 憑證已在別張傳票入帳時只提醒，不擋 |

**怎麼選：**

1. **有發票或收據、是一筆支出**（進貨、費用、設備）→ 憑證歸檔入帳。不管是現金、員工代墊、負責人代墊還是銀行轉帳付的，都一樣；付款方式選對就好。
2. **沒有發票收據的交易**（薪資、勞健保、借還款、業主投入或提取、調整、更正）→ 日記簿「＋ 新增分錄」。有佐證（薪資表、合約、匯款單）就掛附件。
3. **傳票已經在別處產生、只是缺憑證**（自動分錄、購置分錄）→ 日記簿掛附件；自動分錄按「檢視」→「儲存附件」。
4. **銀行轉帳付款、又有發票**：先在憑證歸檔入帳（付款方式選該銀行），再到銀行存摺對帳「手動對應」。已經「補登分錄」了 → 到日記簿刪掉那張補登，改走憑證歸檔。
5. **固定資產有發票**：在憑證歸檔入帳（科目選 15xx），讓系統建立資產；再到「固定資產與折舊」補耐用年數等資料。發票不在手上、要先記帳時，才用「固定資產與折舊 →＋ 新增資產 → 建立購置分錄」，之後發票到了掛在那張購置分錄上。
6. **一張憑證只屬於一張傳票。** 日記簿提醒「已由其他分錄入帳」時，先查清楚再存。
7. **不確定就走憑證歸檔。**

**例子：** 用銀行轉帳付了一張設備維修的三聯式發票。

1. 憑證歸檔上傳照片 → 覆核：科目「修繕費」、付款方式選那個銀行存款、可扣抵 →「入帳並歸檔」。
2. 系統產生「憑證」傳票：借 修繕費（未稅）、借 1261，貸 銀行存款；401 進項清單出現這張發票，扣抵代號 1。
3. 銀行存摺對帳時，那一列支出自動或手動對應到這張傳票。**不要**再按「補登分錄」。

## 八、帳務規則摘要

- **作廢**：品名、選項、備註、付款方式、分類欄中含「老闆測試」「老闆招待」「報廢」→ 金額計 0、不入營收；數量仍計入原物料耗用。POS 狀態為作廢／取消／退款者同樣排除。也可以在銷售明細手動「標記作廢」並寫原因。
- **營收分錄**（一般稅額）：借 1105 現金／在途款項（綠界、LINE Pay…），貸 各品類銷貨收入（含稅 ÷ 1.05）、銷項稅額；折扣列「銷貨折扣」。1101 零用金-門市收銀是找零與備用金，不記營收；門市現金存入銀行：借 銀行存款／貸 1105 現金（存摺補登會自動建議）。
- **寄杯**：預設「收款時開立發票」（依法規），售出當天認列銷項稅額、預收款以未稅金額入帳；兌換時只把預收款轉為收入，不重複計稅。設定可改為「兌換時開立」。
- **進項稅額**：只有統一發票、載明本店統編、非交際應酬或職工福利用途者可扣抵（營業稅法第 19 條），其餘稅額併入成本。伙食費、沒有本店統編的水電電信帳單自動判斷不可扣抵（扣抵代號 3）。
- **撥款**：借 銀行存款，貸 應收帳款－未撥款項（1111 信用卡、1112 LINE Pay、1113 街口、1114 台灣Pay、1115 外送平台）。手續費預設**以綠界／LINE Pay 開的發票入帳**（付款方式選對應的未撥款項），撥款分錄不另記手續費，避免重複；設定可關閉。
- **收銀機發票**載明本店統編、但沒有分開印稅額：稅額＝總額 ÷ 1.05 × 5%，可扣抵。
- **折舊**：平均法，殘值預設「成本 ÷（耐用年數＋1）」。
- **成本**：定期盤存制，本月耗用＝期初＋進貨－期末盤點。
- **傳票號碼**：民國年月＋當月流水號，例如 11509-0001。
- **鎖定**：已鎖定月份的分錄不可新增、修改、刪除，自動分錄也不再更新。

## 九、雲端與 AI（選用）

需要：Supabase 帳號（免費方案即可）、Anthropic API 金鑰（AI 辨識發票用）。

1. 在 [supabase.com](https://supabase.com) 建立專案（Region 選 Tokyo 或 Singapore）。
2. 左側 **SQL Editor** → 貼上 `supabase/migrations/20260923000000_wuyue_erp_init.sql` 全部內容 → Run。這份 SQL 可以重複執行：之後系統更新時再執行一次，就會補上新的資料表與欄位，既有資料不受影響。
3. 同一個 SQL Editor 執行（換成你的 Email）：
   ```sql
   insert into public.app_users (email, role) values ('你的Email', 'owner');
   ```
   只有這張白名單上的 Email 能讀寫資料（資料列級權限 RLS 已設定好，也已實測陌生帳號、未登入者都讀不到任何資料）。
4. **Authentication → Users → Add user**：用同一個 Email 建立帳號並設定密碼。到 **Authentication → Sign In / Providers** 關閉「Allow new users to sign up」（系統只接受 Email＋密碼登入，不開放自行註冊）。
5. 部署 AI 辨識函式：
   - 用 Supabase 後台：**Edge Functions → Deploy a new function → Via Editor**，名稱填 `extract-document`，貼上 `supabase/functions/extract-document/index.ts` 內容後部署；到 **Edge Functions → Secrets** 新增 `ANTHROPIC_API_KEY`。
   - 或用 [Supabase CLI](https://supabase.com/docs/guides/cli)：
     ```bash
     supabase login
     supabase link --project-ref 你的專案代號
     supabase secrets set ANTHROPIC_API_KEY=sk-ant-你的金鑰
     supabase secrets set ALLOWED_ORIGINS=https://sun590928-byte.github.io
     supabase functions deploy extract-document
     supabase functions deploy company-name
     ```
   金鑰只存在 Supabase 伺服器端，網頁與 GitHub 上都不會出現。`ALLOWED_ORIGINS`（選用）限制只有你的網站能呼叫。預設模型 `claude-opus-5`，可用 `CLAUDE_MODEL` 更換。
   - 廠商登記全名（選用）：再用同樣方式部署 `company-name`（貼上 `supabase/functions/company-name/index.ts`，不需要任何金鑰）。本機辨識發票時會用賣方統編到經濟部「商工登記公示資料」查登記名稱，一張照片多張發票以第一張的賣方為準；憑證卡片的廠商欄也有「查全名」按鈕。沒部署也能用，廠商名稱就沿用辨識結果。
6. 打開 ERP → **設定與備份 → 雲端資料庫**：填入 Project URL（`https://xxxx.supabase.co`）與 anon public key（Settings → API）→ 啟用 → 輸入開啟密碼 → 登入雲端帳號。之後這台裝置保持登入（加密保存），每次只要輸入開啟密碼。
7. 若之前已在本機匯入資料，按「把這台裝置的本機資料上傳到雲端」（照片一起上傳）。

### Claude 連接器（MCP）：在 Claude 對話框裡覆核憑證

連上之後，在 claude.ai 或 Claude Code 直接說「幫我覆核待處理的憑證」，Claude 會自己讀照片、填欄位、標記已覆核，不確定的問你；最後你回 ERP 按「全部入帳」。連接器只能碰待覆核的憑證（讀照片、填欄位），不能入帳、不能刪除、碰不到銷售與分錄。

1. 部署函式（一次）：Supabase 後台 → **Edge Functions → Deploy a new function → Via editor**，名稱 `erp-mcp`，貼上 `supabase/functions/erp-mcp/index.ts` → Deploy。（名稱若沒改、被自動命名成例如 `smooth-task`，不用重建，到 ERP 的連接器設定把函式名稱填成一樣的即可。）
2. 同一個函式的設定頁把 **Verify JWT** 關掉（claude.ai 呼叫時不會帶 Supabase 的 JWT；金鑰由函式自己驗證）。
3. ERP → **設定與備份 → Claude 連接器** → 「產生連接器金鑰」，按「測試連線」確認成功。
4. **claude.ai**：設定 → 連接器 → 新增自訂連接器，貼上 ERP 顯示的網址（網址含金鑰，請當密碼保管）。
   **Claude Code**：複製 ERP 顯示的 `claude mcp add …` 指令到終端機執行。
5. 金鑰外洩或換人時按「重新產生金鑰」，舊的立即失效。

限制：只支援雲端模式（本機資料加密在裝置裡）；PDF、HEIC 無法透過連接器讀取，請用 ERP 內的「AI 辨識」。

**更新連接器**：程式更新後，到 Supabase 該函式的 **Code** 分頁，貼上最新的 `supabase/functions/erp-mcp/index.ts` → **Deploy updates**；ERP「測試連線」或開啟 `…/erp-mcp/version` 可確認版本。

### 會計項目表：匯入整份 CSV

在「會計項目」按「匯入科目表 CSV」（格式同「匯出 CSV」：代號、名稱、類別、餘額方向、成本性質、營所稅申報欄位、說明）。匯入前會列出新增、改名、名稱對調、停用的科目，並自動修正明顯的輸入錯誤（例如 1xxx 科目的類別填成「營業費用」、申報欄位填成「借」）。科目表裡沒有、也沒有分錄用到的科目會停用（可再啟用）。每次儲存後系統都會重新讀取確認；頁首會顯示資料存在哪裡（雲端專案或這台電腦），避免改到另一份資料。

## 十、資訊安全

| 保護對象 | 做法 |
|---|---|
| 開啟系統 | 需要**開啟密碼**；閒置（預設 30 分鐘，可調 5 分鐘～4 小時）自動上鎖；另開分頁時舊分頁自動上鎖。 |
| 這台裝置上的資料 | 帳務資料、憑證照片、雲端登入狀態一律以 **AES-256-GCM** 加密後才寫入瀏覽器；金鑰由開啟密碼經 PBKDF2（60 萬次）衍生，密碼本身不儲存。別人拿到電腦也讀不到內容。 |
| 忘記密碼 | 用 25 碼**復原碼**重設（重設後會換一組新的復原碼）；兩者都遺失時，只能清除這台裝置的資料、再從加密備份還原。 |
| 雲端資料 | 存在你自己的 Supabase；只有白名單帳號能讀寫（RLS），照片存私有空間，預覽連結 10 分鐘失效；不開放自行註冊。 |
| 備份檔 | 「下載加密備份」產生 `.wyb` 檔，以備份密碼加密（可含憑證照片），放 OneDrive 或隨身碟也安全。 |
| 網站本身 | 內容安全政策（CSP）只允許載入本站程式與 Supabase；禁止被其他網站嵌入；不被搜尋引擎收錄。 |

**關於公開的 GitHub repo**：repo 裡只有程式碼（就像 App 的安裝檔），**沒有任何營業資料、密碼或金鑰**（已掃描檢查過常見的金鑰格式）。GitHub 無法替 repo 設密碼；可以在 repo 的 **Settings → General → Danger Zone → Change visibility** 改成私有，但要注意：免費方案的私有 repo 無法使用 GitHub Pages（網站會下線，需 GitHub Pro 每月 US$4），而且即使改私有，網站網址仍是公開的。真正保護資料的是上表的開啟密碼、加密與雲端白名單。若想連網站入口都加一道門，可改用 Cloudflare Pages＋Cloudflare Access（免費，限定 Email 驗證後才能開網站）。

**請不要把銷售明細、發票、存摺等資料檔 commit 進 repo**（`.gitignore` 已擋下常見資料檔）。

## 附錄 B：憑證本機辨識怎麼運作

上傳後自動在瀏覽器裡執行（也可按「本機辨識」重跑），不用外部 AI，照片不離開這台電腦：

1. 讀電子發票 **QR 碼**：發票號碼、日期、含稅／未稅金額、買賣方統編、品項，完全精準；一張照片有好幾張發票也讀得到。
2. 依發票號碼對照**財政部電子發票**、**已申報媒體檔**：賣方統編、稅額、課稅別、扣抵代號照申報。
3. 讀不到 QR 碼時做**文字辨識**（繁中＋英數，第一次會下載約 10 MB 辨識資料）：發票號碼、日期（排除列印日期、發票期別）、統編（驗證檢查碼）、金額（未稅＋稅額＝總額交叉驗證、中文大寫金額）。
4. **廠商資料庫**：從你已覆核、已入帳的憑證學習——同一個賣方統編或店名，帶出你以前選的店名、會計項目、付款方式；品項文字也會和以前相似的品項比對。
5. **自動覆核規則**：檔名與照片不一致、買方統編不是本店、發票號碼重複、稅額不是 5%、設備未達 8 萬改列 6135／達門檻列固定資產、交際費／職工福利不扣抵、超商與生活百貨零星採買列 6133、多張收據的彙總、備註寫「不入帳」等。

沒有疑點的標「**已覆核（自動）**」；有疑點的標「**需確認**」並列出原因，「全部入帳」會略過。核對照片後按「暫存」即確認（之後不會再被辨識覆寫，也會被廠商資料庫學起來）。卡片上的「辨識依據」列出每個欄位的來源與判斷理由。設定頁可關閉自動辨識、文字辨識，或調整資本化門檻。連了雲端並部署 AI 函式後，也可以按「**AI 辨識**」讓 Claude 讀出金額、發票號碼與品項，覆核後再入帳。

## 附錄 C：固定資產

- **有發票時（建議）**：憑證歸檔入帳，會計項目選 15xx → 系統問「連結現有資產」或「新增資產」→ 新增的資產自動提列折舊。之後到「固定資產與折舊」補耐用年數等資料。
- **先登錄資產、發票之後才到**：「固定資產與折舊」→「＋ 新增資產」→ 儲存後系統問「要現在建立購置分錄嗎？」→ 分錄視窗已預填 **借 資產科目（未稅成本）、借 1261 進項稅額／貸 付款方式**，可修改後儲存。發票到了，掛在這張購置分錄上（日記簿 → 修改 → 附件）。附上的發票若已在憑證歸檔入帳，系統直接把那張傳票當購置分錄，不重複建立。
- 清單會顯示每項資產的「購置憑證」與「購置分錄」狀態；缺發票、缺分錄會在「每月結帳檢查」提醒。營收起算日前購置的資產列入「期初開帳」。
- 刪除資產時，購置傳票不會跟著刪，請到日記簿處理。
